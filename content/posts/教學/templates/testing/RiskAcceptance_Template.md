# 風險接受單範本（Risk Acceptance）

> **參照標準**：ISO/IEC 27005:2022（風險處理）/ ISO/IEC 27001:2022 6.1.3 / CVSS v4.0、EPSS、CISA KEV
>
> **文件用途**：記錄無法在修補時限內處理的弱點或安全例外：為什麼接受、用什麼補償控制、誰核准、何時重新評估
>
> **適用階段**：測試驗證、上線核准（G3）、維運階段
>
> **範本版本**：v2.0（2026-10-06）｜對應《軟體開發標準程序教學手冊》v2.0 第 9.2 節

## 1. 風險描述

### 📝 範本

| 欄位 | 內容 |
|------|------|
| **單號** | RA-{YYYY}-{序號} |
| **弱點／例外** | {CVE 編號或弱點描述}（CVSS {版本}：{分數}；EPSS {值}（查詢日）；KEV：{是／否}） |
| **影響系統／版本** | {系統與版本} |
| **無法如期處理的原因** | {上游無修補版本／需大幅改版／業務限制} |

### 📖 使用說明

- **列於 CISA KEV 的弱點原則上不得接受風險**，必須在 24 小時內緩解
- 原因必須具體，「時間不夠」不是可接受的原因

### 💡 範例

| 欄位 | 內容 |
|------|------|
| **單號** | RA-2026-07 |
| **弱點／例外** | CVE-2026-12345（commons-foo 2.3.1；CVSS v4.0：7.5 High；EPSS 0.004（2026-10-01）；KEV：否） |
| **影響系統／版本** | HRMS customer-service v2.4.0 |
| **無法如期處理的原因** | 上游尚未發布修補版本 |

## 2. 評估與補償控制

### 📝 範本

| 欄位 | 內容 |
|------|------|
| **可達性分析** | {有弱點的函式是否被呼叫；分析方法與依據} |
| **殘餘風險** | {採取補償控制後的風險描述與等級} |
| **補償控制** | {WAF 規則、關閉功能（Feature Flag）、網路隔離、監控告警} |
| **補償控制驗證** | {如何確認補償控制有效} |

### 📖 使用說明

- 補償控制要能驗證：例如以攻擊樣本測試 WAF 規則確實攔截
- 可達性分析需附依據（程式碼搜尋結果、呼叫圖），供複核

### 💡 範例

| 欄位 | 內容 |
|------|------|
| **可達性分析** | `Foo#parseXml` 僅於管理後台匯入功能使用（`grep -rn "parseXml" src/` 共 1 處） |
| **殘餘風險** | 低：功能已關閉且限內網 ADMIN 權限 |
| **補償控制** | 1. 匯入功能以 Feature Flag `admin-xml-import` 關閉；2. WAF 加入 XXE 特徵規則 |
| **補償控制驗證** | 以 XXE 測試樣本呼叫匯入 API → WAF 回 403；Flag 狀態於 Flag 平台確認為 off |

## 3. 核准與期限

### 📝 範本

| 欄位 | 內容 |
|------|------|
| **接受期限** | {YYYY-MM-DD}（最長 {N} 個月） |
| **到期處理** | {重新評估／修補／延長需重新核准} |
| **核准者** | {資安主管、系統擁有者}，{日期} |

### 📖 使用說明

- 風險接受必須有期限；到期未處理視同違規
- 核准者至少包含資安主管與系統擁有者，PM 或開發者不得自行核准

### 💡 範例

| 欄位 | 內容 |
|------|------|
| **接受期限** | 2026-11-30 |
| **到期處理** | 上游若已發布修補版本則升級；否則重新評估並重新核准 |
| **核准者** | 資安主管 李小華、系統擁有者 陳大文，2026-10-02 |

## 4. 審查與驗證

> 本節供審查者使用，也用來檢查 AI 依本範本產出的風險接受單是否正確。

### 自動檢查

| 檢查項目 | 方法 |
|---------|------|
| KEV 檢查 | 以 CISA KEV JSON 確認 CVE 未列入（`gh api repos/cisagov/kev-data/contents/known_exploited_vulnerabilities.json -H "Accept: application/vnd.github.raw"`） |
| EPSS 值 | `https://api.first.org/data/v1/epss?cve={CVE}` |
| 到期提醒 | 弱點管理系統或工單系統設定到期前 14 天提醒 |
| 掃描例外同步 | 掃描工具的忽略清單（例如 `.trivyignore`）需註明單號與到期日 |

### 人工審查問題

1. 是否為 KEV 弱點？若是，為何未緊急處理？
2. 補償控制是否經實際測試驗證？
3. 核准者是否有權限？期限是否合理？
4. 掃描工具的忽略設定是否會在到期後自動失效？

### AI 常見錯誤

- 捏造 CVSS／EPSS 數值，或未註明查詢日期。
- 補償控制寫成「加強監控」等無法驗證的描述。
- 沒有期限，讓例外變成永久。

---

> 📌 **範本使用注意事項**
>
> 1. 掃描工具的忽略清單必須引用本單號，到期後移除
> 2. 搭配「弱點掃描報告範本」「安全需求清單範本」使用
